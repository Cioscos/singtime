# Karaoke a tracciato — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Un gioco di canto locale: un brano (file o URL YouTube) viene pre-elaborato in un tracciato di note cantabili e giocato nel browser con punteggio basato sul tempo passato sulla nota.

**Architecture:** Backend Python (FastAPI) che esegue una pipeline a cinque passi riavviabili (acquisizione → separazione → altezza → note → testo) e conserva una libreria su disco, una cartella per brano. Frontend nel browser (Svelte + Canvas 2D + Web Audio) che riceve tracciato, testo e audio già pronti e rileva dal vivo solo la voce del giocatore. I due lati si parlano solo tramite i file JSON descritti nel Task 2 e l'API del Task 9.

**Tech Stack:** Python 3.12 (uv), FastAPI, yt-dlp, ffmpeg, PyTorch cu126, audio-separator (BS/Mel-Band RoFormer, Demucs), swift-f0, torchfcpe, faster-whisper, LRCLIB · TypeScript, Vite, Svelte 5, vitest, pitchy (McLeod).

**Spec:** `docs/superpowers/specs/2026-11-19-karaoke-design.md` (mockup: `docs/superpowers/specs/assets/2026-11-19-schermata-gioco.html`)

## Global Constraints

- Python **3.12** gestito da `uv`; il Python 3.14 di sistema non si tocca. Mai `pip install` globale.
- Windows 11, shell PowerShell. Browser di riferimento: Chrome/Edge.
- Il server ascolta solo su `127.0.0.1:8765`. Uniche chiamate esterne: YouTube (yt-dlp), LRCLIB, download dei pesi dei modelli.
- Le richieste a LRCLIB usano `User-Agent: karaoke-tracciato/0.1` e contengono solo artista, titolo, durata.
- Dati in `data/` (override con variabile d'ambiente `KARAOKE_DATA_DIR`); `data/`, `.superpowers/`, `.venv/`, `node_modules/`, `frontend/dist/` stanno in `.gitignore`.
- Tutto il testo mostrato all'utente è in **italiano**.
- Fuori dalla prima versione (spec §2): più giocatori, modifica manuale delle note, cambio tonalità, video, impacchettamento, sillabe sulle barre. Non aggiungerli.
- Se c'è da scegliere, la qualità della separazione viene prima della velocità (spec §6.2).
- I test che usano modelli reali o la rete hanno `@pytest.mark.slow`; `uv run pytest -m "not slow"` deve restare sotto i 30 s.
- Ogni commit termina con la riga `Co-Authored-By: Claude Fable 5.2 <noreply@anthropic.com>`.

### Scostamenti dalla spec, verificati sulle librerie reali

- **RMVPE non esiste come pacchetto installabile.** I candidati per l'altezza diventano `swift-f0` (pari a RMVPE nel suo benchmark, gira su CPU, fotogrammi da 16 ms) e `torchfcpe` (10 ms). L'algoritmo delle note lavora sui tempi reali dei fotogrammi, quindi è indifferente al passo.
- `swift-f0` ha una sua `segment_notes`. L'algoritmo resta il nostro (spec §6.4), ma la prova del Task 13 la mostra come confronto: se risultasse migliore, lo si dice all'utente prima di proseguire.
- `audio-separator` si installa con l'extra `cpu`, non `gpu`: i modelli RoFormer e Demucs girano su PyTorch/CUDA, e l'extra `gpu` porterebbe `onnxruntime-gpu` in conflitto con l'`onnxruntime` richiesto da `swift-f0` e `faster-whisper`.

## Review Focus

Casi che la spec implica ma non nomina, ognuno fissato da un test nel task indicato:

1. **URL di YouTube in forme diverse** (`youtu.be/…`, con `&list=`, `shorts/`, video di un'ora o diretta): si scarica solo quel video; oltre 15 minuti o in diretta si rifiuta con messaggio chiaro. → Task 3
2. **Server chiuso a metà elaborazione**: al riavvio i passi rimasti "in corso" diventano errori riprovabili, non restano bloccati per sempre. → Task 2, Task 9
3. **File LRC reali**: più tempi sulla stessa riga, millisecondi a 2 o 3 cifre, tag `[ar:…]`, righe vuote per gli stacchi strumentali. → Task 7
4. **File caricati non validi o con nomi difficili** (un `.txt`, un `.mp4` con audio, nome con spazi e accenti): il non-audio dà errore chiaro senza lasciare un brano in libreria; gli altri funzionano. → Task 3, Task 9
5. **Scheda nascosta o rallentata durante il gioco**: i buchi tra due letture della voce non contano come tempo preso, il gioco va in pausa da solo, nessuna divisione per zero su tracciati vuoti. → Task 14, Task 18

def curve(segments, hop=0.010):
    """segments: lista di (durata_s, funzione t->midi oppure None per il silenzio)."""
    times, midi, t0 = [], [], 0.0
    for dur, fn in segments:
        n = int(round(dur / hop)); t = np.arange(n) * hop
        times.append(t0 + t); midi.append(np.full(n, np.nan) if fn is None else np.vectorize(fn)(t).astype(float))
        t0 += n * hop
    return PitchCurve(np.concatenate(times), np.concatenate(midi))
